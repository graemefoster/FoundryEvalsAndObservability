## First run

1. Move the four workflow files into `.github/workflows/`, and delete `deploy-and-evaluate.yml`, `local-checks.yml` and `agent-gate.yml`.
2. In the repo settings, create a `production` environment with yourself as a required reviewer.
3. Run each workflow manually with **write_baseline** ticked (PR gate, holdout, release). Download each `baseline-<dataset>` artifact and commit it as `sample/evaluation/baselines/<dataset>.json`. Check each baseline run looks right before trusting it.

Caveats:

- **Every evaluation deploys over the shared demo agent.** That's fine for a demo, but not how you'd run it for real; there you'd deploy each PR to its own agent version.
- **Tolerances depend on set size.** Foundry's 0.03 noise figure is for large optimizer runs. With 8 rows, one binary row moves a mean by 0.125, so the PR gate allows one row. On the 6-row drift set, the must-pass rule does the real work.
- **Untested in GitHub.** The workflows pass actionlint but haven't been run.

## Round 8 (12 October): fix the tools first

The 12/18 baseline showed 4 of 6 failures were the policy search, not the agent: for long keyword
queries, `policy:purchasing` ranked 4th to 9th, because its words ("purchasing", "approval",
"policy") appear in almost every policy and keyword ranking treats them as worthless.

| File | Change |
| --- | --- |
| `sample/agent/tools.py` | `knowledge_base_retrieve` is now hybrid: keyword ranking plus vector similarity, merged by reciprocal rank fusion (as Azure AI Search does), top 5 per query. Falls back to keyword-only, with a logged warning and `"search_mode": "keyword"` in the result, if embeddings are missing, stale or the embedding call fails. `search_ontology` now returns an ID (`ontology:department-budget`) and `"currency": "dollars"`, matching the policies. |
| `sample/agent/build_embeddings.py` (new) | Embeds the policies into `agent/data/policy_embeddings.json` (512 dimensions) with a hash per policy. `--check` fails, offline, if any policy changed since. |
| `sample/azure.yaml` | Adds a `text-embedding-3-small` deployment (GlobalStandard, 50). |

`ask` (Work IQ) now does what real Work IQ did when asked "who is my line manager, are they on
leave, and has anyone been delegated their approvals": it resolves the person and answers about them.
When a result names someone's line manager, or the question names a role such as Hospitality Lead,
`ask` adds that person's directory record (role and leave) and, if the question is about approval or
delegation, their Approvals Register entries. Checked for all 32 employees and the dinner roles.
Real Work IQ has no approval delegations (those live in finance systems); the mock keeps the
register in Work IQ for simplicity, and the talk says so.

Embedding route, tested one by one from the hosted agent: the project OpenAI route returns 404
for embeddings; the account's `services.ai.azure.com` host refuses the agent identity with 401
("Principal does not have access to API/Operation"); the account's
`https://<account>.cognitiveservices.azure.com/openai/v1/` host works, as Microsoft's hosted-agent
permissions page documents. The hosted agent runs as its own agent identity
(`instance_identity.principal_id` in `azd ai agent show`), not the project's identity. Bicep
can't see it, so a `postdeploy` hook in `azure.yaml` runs `infra/grant-agent-embeddings.sh`,
which grants it **Cognitive Services OpenAI User** on the account after every deploy. If the call fails, the tool result carries `fallback_reason`.
